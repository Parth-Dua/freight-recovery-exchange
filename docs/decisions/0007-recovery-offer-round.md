# 0007 — One-shot recovery offer round (Phase 6, Parth's half)

- **Date:** 2026-10-17 · **Status:** Proposed (contract additions need Tisya's OK) · **Phase:** 6
- **Messages (additive, schema 1.0):** `REQUEST_RECOVERY_CAPACITY {recovery_run_id, withdrawn_sailing_id, request_items[], expires_at}` → `RECOVERY_CAPACITY_OFFERS {recovery_run_id, offers[]}` | `REJECT_OFFER` | `AGENT_ERROR`. A carrier may return several sailings in one reply (spec 06 §5), so the reply carries a list; each element is spec 06's `RECOVERY_OFFER`. Decline reuses `REJECT_OFFER` rather than adding a new type.
- **Envelope:** a recovery has no cargo request, so `request_id` is empty and `negotiation_id` = `correlation_id` = the recovery run id.
- **Deviation from spec 06 §5:** `request_items` do **not** carry the buyer's `authorization_envelope` (price ceiling). Carriers price from their own private policy, as for quotes; the allocation enforces each buyer's envelope and flags over-envelope assignments for approval. Sending the ceiling would only invite carriers to price at it.
- **One-shot (AT-06-06):** the Exchange sends exactly one request per active carrier per run, with no retry and no counter path. Carriers log recovery offers with `carrier_offer_log.offer_kind = 'recovery'` and refuse any `COUNTER_OFFER` on them (`COUNTER_LIMIT_REACHED`).
- **Carrier rule:** offer every own ACTIVE, not-yet-departed sailing on the lane, other than the withdrawn one, that can take at least one displaced booking (on time; whole unless the buyer allows a split). Capacity claimed = min(available, sum of eligible quantities); price = the quote policy's unit price × units. At most 5 offers per reply.
- **Exchange checks (message level, step 3):** registered identity, carrier signature, correlation incl. run id; per offer: not the withdrawn sailing, sailing exists in Tiger, owned by this carrier, ACTIVE, route and schedule equal the Tiger record, not departed, not expired, eligible bookings ⊆ request with matching corridor/container/currency and arrival ≤ each deadline, no duplicate offer or sailing in one reply. Invalid offers are stored as `REJECTED` with a typed code and never reach the solver. Capacity claims are checked by Tisya's `AllocationSeam` (step 4).
- **Persistence:** `recovery_runs` (one per withdrawal via the existing UNIQUE `withdrawal_event_id`; spec 07 status vocabulary; `input_version` + `proposal` snapshot of stranded bookings and the `RecoveryProposal`), `recovery_offers` (every offer and its verdict), `agent_messages` and `market_events` keyed by the run id. A duplicate trigger returns the existing run without contacting carriers.
- **Stops at PROPOSED.** Holds, approval, confirmation and superseding are phase 7, starting from a PROPOSED run. A process killed mid-run leaves the run in `OFFERS_REQUESTED`; phase 7 reconciliation must handle that.
