# 0006 — Fetch Agent Payment Protocol + Stripe (spec 04 WP6 investigation)

- **Date:** 2026-10-17 · **Status:** Bonus **NOT VERIFIED**. User (2026-10-17): Payment Protocol is **required** for the product, but **deferred** — Phase 4 ships the hosted Stripe test Checkout link now. · **Owner:** Parth
- **Finding:** Fetch's official example ("stripe horoscope payment protocol", Innovation Lab) shows the Agent Payment Protocol carrying a Stripe **test** checkout: a uAgent includes `Protocol(spec=payment_protocol_spec, role="seller")`, sends `RequestPayment(accepted_funds=[Funds(currency="USD", amount="1.00", payment_method="stripe")], metadata={"stripe": {client_secret, checkout_session_id, publishable_key, currency, amount_cents, ui_mode:"embedded"}})`, the UI replies `CommitPayment(transaction_id=cs_test_…)`, the seller retrieves the session (`payment_status=="paid"`) and sends `CompletePayment` (or `CancelPayment`). Needs `STRIPE_PUBLISHABLE_KEY` (pk_test) in addition to the secret key; checkout session uses `ui_mode="embedded"`.
- The protocol models are installed (`uagents_core.contrib.protocols.payment`: Funds, RequestPayment, CommitPayment, CompletePayment, CancelPayment, RejectPayment).
- **Blocker for us:** the Exchange is an Agentverse-SDK LangGraph agent; its mailbox only parses `ChatMessage`/`ChatAcknowledgement` and replies only with Chat Protocol content, so it can neither send `RequestPayment` nor receive `CommitPayment`. The example is uAgents-only. The example also notes plain ASI:One chat "often won't show the checkout card"; testing is via the Agentverse inspector/chat.
- **Decision now:** Phase 4 uses a Stripe-hosted **test** Checkout link in the chat reply + server-side verification (decision 0005). This satisfies spec 04; it is **not** claimed as Fetch Payment Protocol.
- **Path to the bonus later:** a uAgent gateway (PRD §6.1 / earlier "Option 3") or a uAgent payment front-end that speaks Chat + Payment protocols, reusing `freight_exchange.payments` for session creation/verification (switching to `ui_mode="embedded"`). Touches the ASI:One surface → coordinate with Tisya (CardSeam owner) before building.
